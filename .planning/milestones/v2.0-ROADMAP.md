# Milestone v2.0: JetBrains Plugin

**Status:** ✅ SHIPPED 2026-04-18
**Phases:** 4-8
**Total Plans:** 10

## Overview

File Reference shipped its second milestone by extending the validated VS Code workflow into JetBrains IDEs, preserving deterministic reference formatting, adding native JetBrains actions and feedback, and finishing the build, verification, rename, and marketplace-preparation work needed for a manual release path.

## Phases

### Phase 4: JetBrains Plugin Foundation

**Goal**: Establish the IntelliJ Platform plugin project, compatibility model, and core platform wiring needed for broad JetBrains IDE support.
**Depends on**: Phase 3
**Plans**: 2 plans

Plans:

- [x] 04-01: Create the IntelliJ Platform plugin project, Gradle build, and metadata baseline
- [x] 04-02: Define compatibility, dependency, and module boundaries for broad JetBrains IDE support

**Details:**
Phase 4 created the standalone `jetbrains-plugin/` project, checked in a working Gradle wrapper, patched core plugin metadata through Gradle, verified a runnable development sandbox, and locked the compatibility posture to broad IntelliJ Platform support rather than an IntelliJ-only spike. It also introduced the verifier-backed compatibility matrix, architecture docs, and smoke coverage that kept future JetBrains work grounded in native package boundaries.

### Phase 5: Reference Copy Engine

**Goal**: Implement the JetBrains-side editor validation, line/range normalization, path resolution, and deterministic reference formatting.
**Depends on**: Phase 4
**Plans**: 2 plans

Plans:

- [x] 05-01: Implement editor-state guards and line/range normalization
- [x] 05-02: Implement path resolution and final reference formatting with test coverage

**Details:**
Phase 5 rebuilt the reference engine for JetBrains as pure Kotlin logic around immutable editor snapshots, explicit unsupported-state handling, line and range normalization, relative-path resolution with absolute fallback, and final `path:line` / `path:start-end` assembly. The result preserved the VS Code MVP output contract while giving the JetBrains implementation its own deterministic test coverage.

### Phase 6: JetBrains Action Workflow

**Goal**: Expose the copy workflow through JetBrains-native action surfaces, keyboard-driven access, clipboard integration, and concise user feedback.
**Depends on**: Phase 5
**Plans**: 2 plans

Plans:

- [x] 06-01: Register actions, action visibility rules, and keyboard-driven entry points
- [x] 06-02: Wire clipboard execution and user messaging into the shared copy workflow

**Details:**
Phase 6 connected the JetBrains reference engine to the IDE runtime by adding absolute and relative copy actions, shared workflow execution, visibility guards, direct clipboard writes, and platform-native notifications for both success and failure. This milestone kept the fast, no-confirmation copy flow from VS Code while adapting it to JetBrains action discovery and shortcut conventions.

### Phase 7: Marketplace Readiness

**Goal**: Make the JetBrains plugin build, verification, signing configuration, and listing assets ready for manual marketplace submission.
**Depends on**: Phase 6
**Plans**: 2 plans

Plans:

- [x] 07-01: Add packaging, verification, and signing-ready build configuration
- [x] 07-02: Create JetBrains Marketplace listing assets and release instructions

**Details:**
Phase 7 packaged the plugin release path into a repeatable maintainer workflow by adding build and verification tasks, PyCharm-first Plugin Verifier coverage, environment-based signing and publish inputs, listing copy, packaged icon assets, and manual submission documentation. The result is a release-ready repo state without requiring live marketplace credentials during normal validation.

### Phase 8: Rename plugin and package for clearer product positioning

**Goal**: Rename the VS Code extension and JetBrains plugin to `Copy File Path with Line Numbers (AI Prompt)` across metadata, package/plugin IDs, runtime namespaces, and release docs without changing the product behavior.
**Depends on**: Phase 7
**Plans**: 2 plans

Plans:

- [x] 08-01: Rename public metadata, marketplace copy, and release docs across VS Code and JetBrains
- [x] 08-02: Rename JetBrains namespaces and re-verify both release paths

**Details:**
Phase 8 unified the product identity across both IDE ecosystems. It renamed the VS Code package metadata, JetBrains plugin ID, Kotlin package tree, action IDs, release docs, and marketplace copy, then re-verified both release paths so the renamed product stayed publishable and technically coherent.

## Milestone Summary

**Decimal Phases:**

- None.

**Key Decisions:**

- Expanded into JetBrains only after the VS Code MVP validated the core copy workflow.
- Preserved the deterministic `path:line` and `path:start-end` contract across IDE ecosystems instead of creating platform-specific output variants.
- Kept JetBrains work isolated in `jetbrains-plugin/` so the shipped VS Code toolchain and release path stayed stable.
- Prepared packaging, verification, and marketplace assets without coupling milestone completion to a live JetBrains Marketplace submission.
- Standardized the public product identity as `Copy File Path with Line Numbers (AI Prompt)` while keeping in-IDE labels shorter and task-focused.

**Issues Resolved:**

- Added broad JetBrains IDE support with a verified IntelliJ Platform plugin foundation.
- Recreated deterministic absolute and project-relative reference output with JetBrains-native validation and fallback behavior.
- Added native JetBrains actions, shortcuts, clipboard writes, and success/failure feedback without increasing workflow friction.
- Finished release packaging, verifier coverage, icon assets, and documentation needed for a manual JetBrains Marketplace submission path.
- Removed cross-IDE naming drift by aligning VS Code and JetBrains metadata, namespaces, and docs under one public product name.

**Issues Deferred:**

- Live JetBrains Marketplace publication still requires maintainer credentials and a manual submission event.
- Settings UI, alternate AI-specific formats, and richer JetBrains-only surfaces remain deferred product work.
- The milestone audit closeout was intentionally skipped at user request during archive creation.

**Technical Debt Incurred:**

- Final marketplace upload remains operational rather than automated product behavior.
- The repo now carries multi-platform release surfaces, so future changes must keep VS Code and JetBrains naming and packaging paths aligned together.
