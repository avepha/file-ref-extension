# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-04-17
**Phases:** 1-3
**Total Plans:** 7

## Overview

File Reference shipped its MVP by delivering deterministic file-reference formatting, wiring that engine into VS Code commands with clipboard feedback, and finishing the release and validation work needed for public distribution.

## Phases

### Phase 1: Reference Engine

**Goal**: Users can generate a correct file reference from a supported active editor with deterministic formatting and clear unsupported-state handling.
**Depends on**: Nothing (first phase)
**Plans**: 2 plans

Plans:

- [x] 1.1: Validation and Range Contract
- [x] 1.2: Path Resolution and Reference Formatting

**Details:**
Phase 1 established the pure TypeScript foundation for the extension. It added explicit editor-state validation, normalized line and range handling, POSIX path normalization, workspace-relative resolution, and absolute fallback behavior. Tests locked down unsupported states, reverse selections, Windows-style path fixtures, and final formatting behavior before any VS Code command wiring was introduced.

### Phase 2: Command Workflow

**Goal**: Users can trigger the copy workflow quickly from standard VS Code entry points and immediately get clipboard and feedback results.
**Depends on**: Phase 1
**Plans**: 2 plans

Plans:

- [x] 2.1: Commands, Contributions, and Editor Adapters
- [x] 2.2: Clipboard Write and User Feedback Flow

**Details:**
Phase 2 connected the reference engine to the VS Code runtime. The extension now contributes absolute and relative copy commands, exposes default keybindings across macOS, Windows, and Linux, adapts active-editor and workspace state through a shared command path, writes the final reference directly to the clipboard, and shows concise success or failure notifications without adding extra user friction.

### Phase 3: Release Readiness

**Goal**: Maintainers can publish the extension confidently, and users get the same core behavior across supported desktop platforms.
**Depends on**: Phase 2
**Plans**: 3 plans

Plans:

- [x] 3.1: Package the extension, add release assets, and wire repeatable VSIX validation
- [x] 3.2: Align README command and shortcut docs with the shipped manifest and add drift detection
- [x] 3.3: Remove high-severity audit findings and enforce audit review in release validation

**Details:**
Phase 3 made the MVP publishable. It added release metadata and packaging scripts for Marketplace and Open VSX, documented the maintainer release checklist and cross-platform smoke expectations, tightened VSIX contents, added README drift detection against the manifest, and enforced npm audit checks in both local and CI release validation paths.

## Milestone Summary

**Decimal Phases:**

- None.

**Key Decisions:**

- Built the formatting engine as plain TypeScript data transformations so correctness could be tested without depending on the VS Code host.
- Kept the MVP UX to two commands, shared workflow logic, direct clipboard writes, and minimal toasts.
- Treated release packaging, VSIX hygiene, and dependency audit enforcement as part of the MVP instead of deferring them to post-release cleanup.

**Issues Resolved:**

- Locked down deterministic `path:line` and `path:start-end` output across supported editor states.
- Removed release drift between manifest contributions and README documentation.
- Eliminated high-severity npm audit findings from the release path and made audit review part of shipping.

**Issues Deferred:**

- Maintainer credential setup and the final human publish/smoke steps remain manual operational work.
- Context-menu support, multi-root relative-path polish, and alternate AI-specific formats remain deferred to a future milestone.

**Technical Debt Incurred:**

- Human verification and marketplace publication still depend on manual execution outside the automated test path.
- Planning artifacts accumulated some duplicate Phase 3 summary variants during workflow churn; the milestone archive preserves the shipped outcome while the live roadmap is trimmed for the next milestone.
